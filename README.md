# Datathon 26 · ForteBank — проверка кассовой дисциплины по видео

Сервис принимает видеозапись с камеры над кассой (.mov), ищет визуальные признаки нарушений кассовой дисциплины
и возвращает вердикт, таймкоды, кадры-доказательства, описание и ссылку на норму законодательства РК.
Все модели работают локально; после загрузки весов интернет не нужен.

## Быстрый старт

```powershell
# 1. окружение (Python 3.11, NVIDIA GPU от 6 ГБ)
python -m venv .venv
.\.venv\Scripts\pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
.\.venv\Scripts\pip install -r requirements.txt

# 2. веса моделей (~9 ГБ, один раз) и 4-битная копия VLM (3 ГБ: запуск без пика памяти 8–9 ГБ)
.\.venv\Scripts\python scripts\download_models.py
.\.venv\Scripts\python scripts\quantize_vlm.py

# 3. ключ API для жюри
copy .env.example .env      # затем впишите свой ключ в API_KEYS

# 4. запуск
.\run_server.ps1            # http://localhost:8000
```

### Docker (сервер с NVIDIA GPU от 6 ГБ)

```bash
cp .env.example .env              # впишите ключ API_KEYS
docker compose up -d --build      # при первом старте веса (~9 ГБ) скачаются в ./models
docker compose logs -f            # ждать строку "models ready"
```

Нужны драйвер NVIDIA и NVIDIA Container Toolkit (на Windows — Docker Desktop с WSL2). Образ собран и проверен
на RTX 4050 (6 ГБ): модели занимают ~5 ГБ видеопамяти, видео 15–25 с обрабатывается за 8–20 с.

### Публичный адрес

Сервис слушает порт 8000. Варианты: облачная GPU-машина с публичным адресом (рекомендуется — не зависит от
ноутбука и сети), либо туннель с ноутбука: `ngrok http 8000` (нужен бесплатный аккаунт, есть постоянный домен)
или `cloudflared tunnel --url http://localhost:8000` (в некоторых сетях порт 7844 закрыт).

## API (раздел 10 ТЗ)

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/analyze` | Загрузить видео (`multipart`, поле `file`), в ответ `job_id` |
| GET | `/api/v1/jobs/{job_id}` | Статус `processing` / `done` / `failed` и результат |
| GET | `/api/v1/violation-types` | Перечень распознаваемых нарушений и норм |
| GET | `/api/v1/health` | Проверка доступности |

Ключ передаётся в заголовке `X-API-Key`; без верного ключа — `401`. Результат — по схеме из ТЗ
(`verdict`, `violations[].type / timecode_sec / description / evidence_frames`). Дополнительно в каждом нарушении:
`norm` (документ, пункт, ссылка на adilet, цитата, пометка «толкование» там, где норма прямо не сформулирована),
`confidence`, `type_id`.

```bash
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
curl https://<адрес>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
python scripts/api_client.py https://<адрес> <ключ> video_017.mov   # загрузка + ожидание результата
```

## Как устроено

```
видео ─► декодирование 4 кадра/с ─► RT-DETRv2 (люди, предметы COCO), OWLv2 1 кадр/с (купюры, сумки, документы, чашки, стол)
      ─► сцена во времени: число людей в помещении, входы/выходы, расположение стола/ноутбука,
         устойчивые изменения картинки (дверь), яркость экрана
      ─► правила по времени ─► кандидаты событий
      ─► проверка кандидатов локальной VLM Qwen3-VL-4B (ответ «да/нет» по кропу) ─► отчёт
```

* `app/pipeline/video.py` — чтение видео (последовательное, без seek), кадры хранятся в JPEG.
* `app/pipeline/perception.py` — детекторы RT-DETRv2 и OWLv2.
* `app/pipeline/scene.py`, `doors.py` — люди в помещении (отсев людей за стеклом и отражений), входы/выходы,
  раскладка, изменения сцены.
* `app/pipeline/rules.py` — правила нарушений; `vlm.py` — верификатор; `report.py` — описания и кадры.
* `app/norms.py` — каталог нарушений и норм (цитаты сверены с текстами на adilet.zan.kz, редакции на 17.10.2026).
* `app/main.py`, `app/jobs.py` — API, очередь (один GPU-воркер), веб-интерфейс в `app/static`.

Подход не привязан к координатам конкретного ракурса: стол, ноутбук, пути входа и область двери определяются
по каждому видео заново.

## Модели (все Apache-2.0, коммерческое использование разрешено)

| Модель | Для чего |
|---|---|
| PekingU/rtdetr_v2_r50vd | люди, чашки, сумки, ноутбук (COCO) |
| google/owlv2-base-patch16-ensemble | купюры, сумки, документы, одежда по текстовому запросу |
| Qwen/Qwen3-VL-4B-Instruct (4-bit) | проверка кандидатов вопросом «да/нет», состояние сейфа |

## Распознаваемые нарушения

Полный перечень норм для кейса — что сервис распознаёт, что видно на видео, но пока не распознаётся, правильное
поведение кассира и что по видео не проверяется — в [`docs/NORMS.md`](docs/NORMS.md). Ниже — краткая версия.

| Тип | Как распознаётся | Норма |
|---|---|---|
| Наличные или ценности оставлены без присмотра | помещение пустеет, на столе остаются купюры/сумка/документы | НБРК № 231, п. 20 ч. 2; п. 22, если обслуживание не закончено |
| Наличные предыдущего клиента на рабочем месте | клиент ушёл, купюры лежат на столе, входит следующий | НБРК № 231, п. 20 ч. 2 |
| Пересчёт принятых наличных после ухода клиента | клиент вышел, купюры ещё на столе/в работе | НБРК № 231, п. 20 ч. 1; п. 31 пп. 4 |
| Сейф оставлен открытым | VLM: дверца открыта, кассир сел за стол или вышел | НБРК № 231, п. 20 ч. 2, п. 80 (толкование) |
| Рабочая станция не заблокирована | кассир ушёл, экран остаётся ярким относительно кадра | АРРФР № 53, п. 73 пп. 6, п. 71 пп. 9 (толкование: требования к банку) |
| Дверь кассы оставлена открытой | после входа картинка у двери не возвращается к исходной | НБРК № 14, п. 16 пп. 1, п. 8 (толкование) |
| Постороннее лицо | человек входит через оставленную открытой дверь | НБРК № 49, п. 41 (обменная касса); АРРФР № 21, п. 16 пп. 4 (толкование) |
| Второе лицо у кассы во время операции | в помещении одновременно 3+ человека | НБРК № 231, п. 20 ч. 2 (толкование) |
| Приём инкассаторской сумки без проверки | посетитель с сумкой уходит через несколько секунд | НБРК № 231, п. 24 |
| Личные вещи на рабочем месте | сумка/одежда на столе, подтверждено VLM | НБРК № 231, п. 12 |
| Приём пищи или напитков | чашка/бутылка у лица, подтверждено VLM | НБРК № 231, п. 12 (толкование) |
| Мобильный телефон | в каталоге; детектор выключен (в разметке Х-10 смартфон кассира не нарушение) | НБРК № 231, п. 12 |

Полные названия актов, пункты, дословные цитаты и ссылки — в `app/norms.py` и в ответе API (`norm`); цитаты
проверены по официальным текстам.

## Нормативные источники

Только действующие акты РК; тексты и редакции сверены на adilet.zan.kz по состоянию на 17.10.2026.

| Акт | Что берём |
|---|---|
| [Постановление Правления НБРК от 29.11.2019 № 231](https://adilet.zan.kz/rus/docs/V1900019680) — Правила осуществления кассовых операций и операций по инкассации | п. 12 (личные вещи и средства связи вне кассового узла), п. 20 (приём и пересчёт в присутствии клиента; на рабочем месте только деньги обслуживаемого клиента, остальное — в закрывающихся хранилищах), п. 21, п. 24 (проверка сумки и пломбы при приёме) |
| [Постановление Правления НБРК от 24.02.2020 № 14](https://adilet.zan.kz/rus/docs/V2000020075) — Правила организации охраны и устройства помещений банков | п. 8, п. 16 пп. 1 (изолированный кассовый узел, касса с запираемой дверью) |
| [Постановление Правления НБРК от 04.04.2019 № 49](https://adilet.zan.kz/rus/docs/V1900018545) — Правила обменных операций | п. 41 (посторонние в кассе обменного пункта) |
| [Постановление Правления АРРФР от 03.04.2026 № 53](https://adilet.zan.kz/rus/docs/V2600038336) — Требования к информационной безопасности банков | п. 71 пп. 9 (блокировка рабочей станции), п. 73 пп. 6 (работа под чужой учётной записью) |
| [Постановление Правления АРРФР от 30.04.2024 № 21](https://adilet.zan.kz/rus/docs/V2400034348) — Инструкция по антитеррористической защите РКО | п. 16 пп. 4 (бесконтрольное пребывание посторонних в критических зонах) |

Как сопоставляем: каждое правило детектора описывает наблюдаемое действие (что видно в кадре) и ссылается на
пункт, который это действие регулирует. Если пункт прямо запрещает действие — даём цитату. Если запрет выводится
из нормы (например, открытый сейф при обязанности хранить деньги в запирающихся устройствах), в ответе есть поле
`interpretation` с объяснением. Утратившие силу акты (НБРК № 58 от 2001 г., № 250 и № 254 от 2012 г.,
НБРК № 48 от 2018 г.) не используются, хотя их тексты ещё встречаются в поиске.

## Качество на обучающем датасете

`scripts/build_cache.py` считает детекции один раз, `scripts/eval.py --vlm` сравнивает с разметкой
(вердикт по видео и ошибка таймкода). Текущая версия: верный вердикт 35 из 40 видео, ложных срабатываний 0,
медианная ошибка таймкода 2.2 с; построчно — `docs/eval_train.txt`, разбор видео — `docs/DATASET.md`.

## Ограничения

* Сервис фиксирует только то, что видно в кадре; правильность проводок, сверки и документов не проверяется.
* Не распознаются: утаивание части денег руками, отсутствие проверки удостоверения, обход счётчика вручную —
  действия слишком мелкие для разрешения записи.
* Открытая дверь определяется, если она остаётся открытой до конца записи; дверь, открытая в середине и затем
  закрытая, может быть пропущена.
* Люди за стеклянной стеной отсеиваются по размеру и положению в кадре; при съёмке очень издалека пороги
  могут потребовать подстройки (`app/pipeline/scene.py`).
* Результат — подсказка проверяющему, а не юридическое заключение. Пункты с пометкой «толкование» не являются
  прямым запретом в акте.
